# Nodi ドキュメント形式 v1

旧形式の仕様。現行形式は [v2](document-format-v2.md)。v1 ファイルは読み込み時に v2 へ移行する。

Nodi の最初の編集・保存機能で使用する最小のドキュメント形式。描画プロパティや AI 操作の詳細は、この形式を使った一連の編集体験を確認してから追加する。

ファイルの拡張子は `.nodi` とし、中身は以下の JSON 形式で保存する。

## 目的

AI が ID だけで要素を示しても人には識別しにくい。すべての要素に人が読める名前を持たせ、正確な参照には ID を使う。

## 保存例

```json
{
  "version": 1,
  "children": [
    {
      "id": "nd_01JABC",
      "name": "ログイン画面",
      "type": "frame",
      "x": 0,
      "y": 0,
      "width": 390,
      "height": 844,
      "children": [
        {
          "id": "nd_01JDEF",
          "name": "ログインボタン",
          "type": "rectangle",
          "x": 24,
          "y": 680,
          "width": 342,
          "height": 48
        }
      ]
    }
  ]
}
```

## v1 の構造

- ルートは `version: 1` とトップレベルの `children` 配列を持つ。トップレベル要素の座標はドキュメント上の座標。
- 各要素は `id`、`name`、`type`、`x`、`y`、`width`、`height` を持つ。子要素の座標は親フレームの左上を基準とする。
- v1 の `type` は `frame` と `rectangle` のみ。`frame` は `children` 配列を持ち、`rectangle` は子を持たない。
- `x` と `y` は有限の数値。`width` と `height` は 0 より大きい有限の数値。

## 識別と編集の規則

- `id` はアプリが生成する不透明な文字列で、ドキュメント内で一意。保存・再読込、名前変更、移動、親の変更で変えない。複製時は複製した要素とその子孫すべてに新しい ID を割り当てる。
- `name` は空白だけではない文字列で、作成時に必ず設定する。ユーザーと AI が変更でき、同名の要素も許可する。要素の参照先を決めるキーには使わない。
- 名前が指定されない作成操作では、アプリが種類に応じた名前（例: `矩形 1`）を付ける。保存データに無名の要素は作らない。
- 編集コマンドは `id` で対象を指定する。作成コマンドは `name` を指定でき、結果には割り当てられた `id` と `name` の両方を返す。
- AI が要素を説明するときは、名前だけ・ID だけでなく、親階層を含めた表示名と ID を一緒に示す（例: `ログイン画面 › ログインボタン (nd_01JDEF)`）。同名の要素は ID で区別する。UI では参照先を選択・表示できるようにする。

## バージョン管理

読み込み時に `version` を確認する。未対応の新しいバージョンを古い形式として解釈しない。保存形式を変更する際はバージョンを進め、旧形式からの変換を用意する。v1 のフィールドを暗黙に別の意味へ変更しない。

## 最初の検証シナリオ

名前付きの矩形を作成し、キャンバスで選択・移動・改名する。保存して開き直し、階層、名前、ID、位置、サイズが保持されていることを確認する。
