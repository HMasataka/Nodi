# Nodi ドキュメント形式 v1

Nodi の現在のドキュメント形式。未リリースで v1 の利用者がいないため、バージョン番号は 1 のまま構造を再設計した。スタイルがノード直下にある以前の開発版のファイルは読み込まず、移行処理も設けない。

ファイルの拡張子は `.nodi` とし、中身は以下の JSON 形式で保存する。

## 目的

AI が ID だけで要素を示しても人には識別しにくい。すべての要素に人が読める名前を持たせ、正確な参照には ID を使う。

## 保存例

```json
{
  "version": 1,
  "children": [
    {
      "id": "nd_01JABC",
      "name": "ログイン画面",
      "type": "frame",
      "x": 0,
      "y": 0,
      "width": 390,
      "height": 844,
      "style": { "fill": "#ffffff" },
      "children": [
        {
          "id": "nd_01JDEF",
          "name": "ログインボタン",
          "type": "rectangle",
          "x": 24,
          "y": 680,
          "width": 342,
          "height": 48,
          "style": {
            "fill": "#f3d9c8",
            "stroke": { "color": "#d9bbaa", "width": 1 },
            "cornerRadii": { "topLeft": 2, "topRight": 2, "bottomRight": 2, "bottomLeft": 2 }
          }
        }
      ]
    }
  ]
}
```

## v1 の構造

- ルートは `version: 1` とトップレベルの `children` 配列を持つ。トップレベル要素の座標はドキュメント上の座標。
- 各要素は `id`、`name`、`type`、`x`、`y`、`width`、`height` と、種別ごとの `style` を持つ。子要素の座標は親フレームの左上を基準とする。内側線の幅は子要素の原点に影響しない。
- 共通の `opacity` は0〜1の有限値で、未指定なら1。保存時は1を省略する。塗り色のアルファとは異なり、塗り・線・文字・フレームの子を描画した後に要素全体へ一度だけ掛ける。フレームでは背景・子・辺線をまとめて合成する。子のマスク・クリップ・画像フィルターを先に適用し、入れ子フレームの不透明度は内側から順に合成する。マスク形状には影響しない。
- 共通の `shadow` は単一の外側影 `{ "color": "#00000080", "offsetX": 0, "offsetY": 4, "blur": 8 }` または `null`。未指定なら `null`、保存時は `null` を省略する。色は6桁／8桁HEX、オフセットはpx単位の有限値、ぼかしは0以上の有限値。塗り・文字・透過画像・フレームの子を含む描画済みのシルエットへ影を付け、親のマスク／クリップで切った後に要素全体の `opacity` を掛ける。影のオフセットは要素とともに回転し、マスク自身の影は描かない。
- v1 の `type` は `frame`、`rectangle`、`ellipse`、`text`、`image`。`frame` は `children` 配列を持ち、それ以外は子を持たない。
- `children` の順番は背面から前面への描画順。同じ親の子要素だけを並べ替え、ID・親基準の座標は変わらない。レイヤー一覧は前面の要素を上に表示する。
- `text` も子を持たず、要素名 `name` とは別の文字列 `content` を持つ。`style` 内の `fontSize` は正の有限値、`color` は `#RRGGBB` または `#RRGGBBAA` 形式、`textAlign` は `left`・`center`・`right` で、いずれも必須。本文には空文字や改行も使用できる。テキスト枠は固定幅・固定高で、幅に応じて折り返し、高さを超えた内容は表示しない。
- 折り返しは単語境界を優先し、枠に入らない長い単語は文字単位で分ける。明示改行と空行は維持し、編集画面と PNG は同じ行構成を使う。
- `text` の `marks` はノード直下の省略可能な装飾範囲の配列。各範囲は本文の UTF-16 位置を示す `start`（含む）と `end`（含まない）を持ち、`color`、`fontWeight`、`underline: true`、`code: true` のうち1つ以上を指定する。範囲は文字（結合した絵文字を含む）の境界で始まり終わり、昇順で重複しない。省略時は装飾なしとして扱う。`code` は等幅フォントと淡い背景で表示する。
- プロパティの本文欄で範囲を選んで装飾を付け外しできる。編集中の本文への装飾は本文と装飾範囲を一つの編集として保存し、既存の別属性の装飾は保持する。
- `text.style` の `fontFamily` は `default`（Avenir Next、ヒラギノ角ゴ、游ゴシック、sans-serif の順）、`system`（システム UI 系）、`serif`（Georgia 系）、`monospace`（等幅系）から選べる。`fontWeight` は 100〜900 の 100 刻み。Wire 形式では省略可能で、省略時は `default`・400 に補完する。編集画面と PNG は同じフォントの代替順を使う。
- `text.style` の `lineHeight` は文字サイズに対する正の有限な倍率、`letterSpacing` は px 単位の有限な数値。字間は負値で詰めることもできる。Wire 形式では省略可能で、省略時は行高 1.4 倍・字間 0px に補完する。
- `x` と `y` は有限の数値。`width` と `height` は 0 より大きい有限の数値。
- 矩形とフレームの `style` は共通の `BoxStyle`（`fill`・`stroke`・`cornerRadii`・`border`）。`fill` は必須の `#RRGGBB`・`#RRGGBBAA` または `null`（塗りなし）。フレームの `background` は廃止した。
- 色はCSSのHEX表記で、8桁の場合は末尾の `AA` がアルファ値（`00` は透明、`ff` は不透明）。6桁は不透明として従来どおり読み書きする。塗り・線・辺線・テキスト・部分装飾の色に共通し、重なる要素は描画時に合成する。
- 矩形・楕円・フレームの `fill` は単色と `null` に加え、`{ "type": "linear", "start": { "x": 0, "y": 0 }, "end": { "x": 1, "y": 0 }, "stops": [{ "position": 0, "color": "#ffffff" }, { "position": 1, "color": "#000000" }] }` を指定できる。始点・終点は異なる要素ローカルの正規化座標（各0〜1）で、サイズ変更に追従し要素とともに回転する。ストップは2個以上、位置は0〜1の昇順で同位置も可。色は6桁／8桁HEX。線と文字色は単色のみ。
- 放射状の塗りは `{ "type": "radial", "center": { "x": 0.5, "y": 0.5 }, "radius": 0.5, "stops": [...] }`。中心の2座標は0〜1、半径は0より大きく1以下の有限値で、要素の短辺に掛けてpxに変換する。これにより縦横比が変わっても円形を維持し、回転時は要素ローカルの中心に追従する。ストップの規則と色形式は線形と共通。楕円形の放射状塗りや複数焦点は扱わない。
- `stroke` は `{ "color": "#RRGGBB", "width": 1 }`（8桁色も可）または `null`（線なし）。幅は 0 以上の有限値で、均一な内側線として描画する。省略時は `null`。幅 0 の線は明示した色とともに保持し、`null` に置き換えない。
- `border` は矩形・フレームだけが持つ、`top`・`right`・`bottom`・`left` ごとの `{ color, width }`。省略した辺は線なし。既定の空オブジェクトは保存しない。初版では角丸（4隅のいずれかが非0）との併用を拒否する。
- `cornerRadii` は `topLeft`・`topRight`・`bottomRight`・`bottomLeft` の4隅のオブジェクト。各値は 0 以上の有限値。オブジェクト全体の省略時は全隅 0 に補完する。指定する場合は4隅とも必須。単一値の `cornerRadius` は廃止し、同梱サンプルの旧角丸は全隅同値で再生成した。
- フレームの `clipContent` はノード直下の真偽値。省略時は `true` に補完する。`true` なら子要素をフレームの輪郭で切り取り、`false` ならはみ出しを表示する（書き出し対象フレーム自体の外は PNG に含まれない）。
- 楕円の `style` は `fill`・`stroke` のみで、`cornerRadii` は持たない。
- 矩形・楕円は `isMask: true` を指定すると、同じ親でその直後から次のマスクまでの兄弟要素を形状でクリップする。マスク自身は描画せず、塗りと線の色は使わない。未指定は `false` に補完し、保存時は省略する。`isMask: false` を Wire に明示した場合は拒否する。マスクの削除・並べ替えで対象の兄弟が変わり、複製ではマスク設定も引き継がれる。
- 編集画面の範囲選択・スナップは回転後の要素AABBを使う。マスク自身と完全に隠れた兄弟は対象外とし、一部見える兄弟はマスクや親フレームのAABBで切り取った範囲を使う。楕円・角丸の輪郭そのものではなくAABB近似で判定する。
- 画像は `source` に PNG・JPEG・WEBP・SVG の data URI と `style` を持つ。画像は `.nodi` 内に埋め込むため、ファイルを単体で移動しても参照が切れない。画像データは 8,000,000 文字以下。
- `image.style.filters` は `brightness`・`contrast`・`saturate`（0 以上の有限値、既定 1）、`grayscale`・`sepia`（0〜1、既定 0）、`hueRotate`（有限の度数、既定 0）を指定できる。適用順はこの記載順。Wire 形式では全項目省略可能で、保存時は既定値の項目だけを除去する。画像の `fit`・`focalPoint`・`cornerRadii` と組み合わせられる。

## Wire 形式と内部モデル

`src/persistence/format.ts` の `WireDocument` / `WireNode` は保存用の省略可能な形式。`src/document/types.ts` の `Document` は既定値を補完した内部モデルで、編集・描画・履歴はこの型を使う。

- `parseDocument`: JSON を読み取り、Zod で検証してから、子孫も含めて既定値を補完する。
- `serializeDocument`: 正規化済みの内部モデルをWireとは別のスキーマで検証し、既定値を除去したWire形式を再検証してJSONを生成する。入力の文書は変更しない。内部で必須の `isMask: false` はWireでは省略し、Wireに明示された `false` は拒否する。
- 保存時に除去する値は、`stroke: null`、全隅 0 の `cornerRadii`、`clipContent: true`、文字の `fontFamily: "default"`・`fontWeight: 400`・`lineHeight: 1.4`・`letterSpacing: 0`。
- `fill: null` は塗りなしを表す必須値なので保存する。画像の `style: {}` も保存する。
- ルート・ノード・スタイル・線・角丸・文字装飾は `z.strictObject` で未知項目を拒否する。省略可能な項目でも不正な値を既定値に置き換えることはない。

作成時の見た目と Wire 形式の既定値は別。新しい矩形は従来の塗り・幅 1 の線・全隅 2、新しいフレームは白い塗りで作る。

## 識別と編集の規則

- `id` はアプリが生成する不透明な文字列で、ドキュメント内で一意。保存・再読込、名前変更、移動、親の変更で変えない。複製時は複製した要素とその子孫すべてに新しい ID を割り当てる。
- `name` は空白だけではない文字列で、作成時に必ず設定する。ユーザーと AI が変更でき、同名の要素も許可する。要素の参照先を決めるキーには使わない。
- 名前が指定されない作成操作では、アプリが種類に応じた名前（例: `矩形 1`）を付ける。保存データに無名の要素は作らない。
- 編集コマンドは `id` で対象を指定する。作成コマンドは `name` を指定でき、結果には割り当てられた `id` と `name` の両方を返す。
- AI が要素を説明するときは、名前だけ・ID だけでなく、親階層を含めた表示名と ID を一緒に示す（例: `ログイン画面 › ログインボタン (nd_01JDEF)`）。同名の要素は ID で区別する。UI では参照先を選択・表示できるようにする。

## バージョン管理

読み込み時に `version: 1` と必須項目を厳密に検証し、それ以外は拒否する。公開前の開発版同士での後方互換は保証しない。形式を公開した後に互換性と移行方針を決める。

## 最初の検証シナリオ

名前付きの矩形を作成し、キャンバスで選択・移動・改名する。保存して開き直し、階層、名前、ID、位置、サイズが保持されていることを確認する。
