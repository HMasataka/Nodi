# Nodi のUIデザイン

`nodi.nodi` をNodiで開く。
メインの編集画面（1440×960px）をグレースケールで描き、左右のパネルを開いた状態、閉じた状態、タイムラインを開いた状態を並べている。
どの画面も同じ文書を開き、同じカード（Project card）を選択している。

## 画面の構成

- **パネル**：左にレイヤー（240px）、右にプロパティ（280px）を置き、どちらも画面の上端から下端まで伸ばす。閉じるとキャンバスが画面全体に広がる。
- **ファイルのチップ**：キャンバスの左上に、開いているファイル名を角丸のチップで浮かせる。チップの先頭のボタンで左パネルを開閉する。
- **操作のチップ**：キャンバスの右上に、倍率とプレビューのアイコンを置く。末尾のボタンで右パネルを開閉する。
- **作成ツール**：キャンバスの下中央に浮かせる。末尾のボタンでタイムラインを開閉する。
- **タイムライン**：左右のパネルの間で、キャンバスの下端から228pxを占める。パネルは画面の上端から下端までの長さを保ち、キャンバスが縮む。作成ツールはタイムラインの12px上に移る。

二つのチップと作成ツールは、パネルやタイムラインを開閉してもキャンバスの端から12pxの位置を保つ。

## タイムラインを開く動線

タイムラインは二つの入口から開く。

- 作成ツールの末尾のボタン。選択中の要素の最初のアニメーションを開く。
- プロパティの「アニメーション」に並ぶ行。押した行のアニメーションを開く。「＋」で追加したアニメーションもタイムラインで開く。

タイムラインには、アニメーションの切り換えと追加と削除、トリガー、長さ、遅延、繰り返し、再生と現在時刻、プロパティごとのトラック、選んだキーフレームの時刻、値、イージング、再生位置へのキーフレームの追加と削除を並べる。
アニメーションの設定はタイムラインにまとめ、プロパティにはアニメーションの一覧だけを置く。
アプリ名はどこにも出さない。
元に戻す、やり直す、保存はショートカットで操作するので、UIには置かない。

## 共通の約束

色は10段階のグレースケールパレットを参照する。
フレームの余白と間隔は `Space / 0・4・8・12・16・20・24・32` を参照する。
アイコンボタンは32px高、入力欄は28px高、レイヤー行は28px高にしている。

パネル、チップ、作成ツール、アートボード、カード、入力欄、アイコンボタンは `components` に定義し、`instance` で使う。
文言の違いはインスタンスの `overrides` に格納する。

## 更新と検証

`build.mjs` がこのモックの生成元。
`.nodi` を直接編集してから生成すると、その編集は置き換わるため、生成元にも変更を反映する。

```bash
node designs/build.mjs
pnpm exec vitest run tests/design-documents.test.ts
```

`node designs/preview.mjs` で `.local/nodi-design-preview.html` を生成できる。
現行アプリと同じ参照解決と自動レイアウトを通した確認用HTMLで、実アプリのスクリーンショットではない。

テストでは、保存と再読込、共通定義の利用、選択枠がカードと一致すること、チップがキャンバスの角に付くこと、タイムラインがパネルの間のキャンバス下端を占めること、子要素が親の領域からはみ出さないことを確認する。
